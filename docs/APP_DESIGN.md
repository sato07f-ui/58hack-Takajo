# アプリ概要
スーパーをダンジョンと見立て、スマホにカメラに映った食材に対応する3Dの敵キャラがAR空間に生成され描画される。ユーザーはボタンで魔法をクリックして敵に攻撃する

## 食材認識
候補:
- Vision API（Claude / Gemini / Google Vision）: 精度高、APIキー必要、何でも認識できるが1回2〜4秒
- ブラウザ内MLモデル（TensorFlow.js 転移学習）: オフライン、高速、学習させた食材しか認識できない
- バーコード / 用意したマーカーを読む: 確実だがリアル感は減る

決定した方式: TensorFlow.js で学習させたモデルで認識する。認識できなかった場合は Gemini の画像認識にフォールバックする

### TensorFlow.js 学習方式の詳細

#### 概要
- 学習済み MobileNet（画像 → 特徴ベクトル）を凍結し、その後ろに食材を分類する小さな層を追加して学習する（転移学習）
- 数十〜数百枚の写真で実用精度が出る
- 推論はブラウザ内で完結し、画像をサーバーに送らない

#### 学習フェーズ（開発中に1回）
1. 認識対象の食材を決める（5〜10 種類）: ここに記入
2. 各食材をスマホで 30〜100 枚撮影する。本番に近い条件（スーパーの照明・角度・袋入り）で撮る
3. 「食材ではない」クラス（棚、床、手など）も同程度撮る。これがないと何を映しても食材と判定される
4. 学習する。手段は次のどちらか
   - Teachable Machine（Google）: ブラウザで画像をクラス別に入れて Train。コード不要、TF.js 形式でエクスポート可
   - 自前コード: MobileNet の出力に `tf.sequential` で分類層を追加し `model.fit`
5. `model.json` と重みファイル（数MB）を `public/model/` に置いて配信する

使用する学習手段: ここに記入

#### 実行フェーズ（アプリ動作中）
1. 起動時に `tf.loadLayersModel('/model/model.json')` で読み込む（初回 1〜3 秒）
2. カメラの `<video>` フレームを 224×224 に縮小してテンソルに変換
3. `model.predict` で各クラスの確率を得る
4. 数フレーム連続で同じクラスが閾値（0.8 程度）を超えたら「認識した」とする
5. 閾値を超えない状態が続いたら Gemini にフォールバックする（条件: ここに記入）
6. 認識結果のラベル文字列を敵生成に渡す

1 フレームの推論はスマホで 30〜100ms

#### 敵生成との接続
- TF.js はラベル文字列しか返さないため、敵の特徴（色・属性など）はラベルから導出する
- 方法（どちらかを選ぶ）: ここに記入
  - D1 に「食材 → 敵パラメータ」の対応表を持つ（AI 呼び出しなし、完全オフライン）
  - ラベルを Workers に送り、テキストのみで LLM に敵パラメータ JSON を作らせる

#### 注意点
- TF.js 本体 約 1MB + MobileNet 約 4MB。初回読み込みが数秒増える
- iOS Safari は WebGL バックエンドで動くが、古い端末はメモリ不足で落ちることがある。デモ端末で早めに検証する
- 精度はモデルではなく学習データで決まる。本番と違う場所・照明で撮ると当日だけ当たらない
